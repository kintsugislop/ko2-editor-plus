# KO2 Editor Plus на GitHub

[Страница проекта](https://github.com/kintsugislop/ko2-editor-plus) содержит исходники и README. На [странице релизов](https://github.com/kintsugislop/ko2-editor-plus/releases) музыкант выбирает версию и скачивает ZIP для Mac. Приложение запускает локальный сервер на компьютере владельца сэмплера.

## Первый запуск скачанной версии

1. Открой релиз, разверни **Assets** и скачай файл с окончанием **-macOS.zip**. Распакуй архив целиком. Для обновления распакуй новую версию в отдельную папку.
2. При первом запуске нужны Python версии 3.9 или новее и инструменты Apple. В Terminal можно проверить их командами `python3 --version` и `clang --version`. Если macOS предложит установить инструменты, дождись окончания установки. Установку можно запустить командой `xcode-select --install`.
3. Подключи K.O. II по USB и открой **KO2 Station.app** рядом с папкой **src**. Альтернативный запуск для неподписанного приложения — ввести в Terminal `cd `, перетащить сюда распакованную папку, нажать Enter и выполнить `sh src/station`.
4. В браузере открой **Project**, выбери проект и нажми **Read from device**. Переключатель **4 groups / Sample tracks** находится наверху. Во вкладке **Library → Folders** выбери свои папки, в **Record** выбери аудиовход. Для остановки нажми **Control-C** в окне Terminal, где запущено приложение.
5. Чтобы перенести сессии из старой копии, закрой обе версии и скопируй старую папку **data** в свежую распаковку до первого запуска. Она содержит локальные проекты, бэкапы, экспорты и настройки путей. Записи из отдельно выбранной папки Takes и сэмплы из Library лежат в исходных местах. Черновики редактора хранятся в том же профиле браузера по адресу приложения.

## Как выпустить следующую версию

Команды ниже выполняются в папке проекта. В примере следующая версия — **0.1.1**. Подставляй один и тот же номер во всех шагах.

1. Обнови краткое описание изменений в README, ссылку на релиз и номер версии в `KO2 Station.app/Contents/Info.plist`. В `CFBundleShortVersionString` укажи 0.1.1, в `CFBundleVersion` увеличь номер сборки.
2. Проверь приложение. Запусти тесты, затем открой редактор и проверь изменённые функции. Для аудиоэкспорта хороший контроль — импортировать WAV на отдельные дорожки с одного старта, затем проверить темп, маркеры и разницу между Scenes и Song.

   ```sh
   python3 -m unittest discover -s tests -v
   sh src/station
   ```

3. После остановки приложения посмотри список изменений. Вручную проверь имена подготовленных файлов и содержимое текстовых правок. Папки `data/` и `temp/`, кэш Python и собранные на твоём Mac помощники исключены через `.gitignore`. Файлы из личной библиотеки, записи и резервные копии оставляй в их локальных папках.

   ```sh
   git status --short
   git add --update
   git add -- docs src tests
   git diff --cached --stat
   git diff --cached
   ```

   Для нового файла в корне используй `git add -- имя-файла`. Если в список случайно попал файл, убери его из будущего коммита командой `git restore --staged -- имя-файла`. Выйти из просмотра изменений можно клавишей **q**.

4. Сохрани версию и отправь основную ветку и её тег на GitHub.

   ```sh
   git commit -m "Release KO2 Editor Plus 0.1.1"
   git tag v0.1.1
   git push origin main
   git push origin v0.1.1
   ```

5. Собери ZIP строго из опубликованного тега. Так архив будет совпадать с исходниками этой версии. Распакуй его отдельно и проверь первый запуск оттуда.

   ```sh
   git archive --format=zip --prefix=KO2-Editor-Plus-0.1.1/ -o /tmp/KO2-Editor-Plus-0.1.1-macOS.zip v0.1.1
   ```

6. На странице проекта открой **Releases → Draft a new release**. Выбери существующий тег **v0.1.1**, введи заголовок **KO2 Editor Plus 0.1.1**, опиши изменения в нескольких строках. Вложения находятся под текстом. Перетащи туда ZIP из шага 5 и нажми **Publish release**. В окне выбора файла на Mac нажми **⌘⇧G**, чтобы ввести путь из команды.
7. Открой опубликованный релиз. Проверь ссылку в README и скачай архив из **Assets**. Старые версии сохраняй под их первоначальными тегами. Для исправления после публикации выпускай следующий номер.

[Справка GitHub по созданию и редактированию релизов](https://docs.github.com/en/repositories/releasing-projects-on-github/managing-releases-in-a-repository)
